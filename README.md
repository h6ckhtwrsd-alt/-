# ⚡ كهرباء الآن — Electricity Now

> الكهرباء في منطقتك.. لحظة بلحظة

منصة تفاعلية يبلّغ فيها المواطنون عن توفّر الكهرباء في أحيائهم (ولاية نهر النيل أولاً)، وتُحسب منها ساعات التشغيل والانقطاع تلقائياً.
**Next.js 14 (App Router) + Tailwind CSS + Supabase (PostgreSQL, Auth, Realtime)**.

## التشغيل خطوة بخطوة

1. **أنشئ مشروعاً في Supabase.**
2. من *SQL Editor* شغّل بالترتيب:
   - `supabase/migrations/0001_init.sql` (الجداول، الصلاحيات RLS، دوال التحقق والإحصائيات، Realtime)
   - `supabase/seed.sql` (ولاية نهر النيل + المحليات السبع + حي «كل المدينة» لكل محلية). **لا تُضاف أي بيانات كهرباء.**
3. **تفعيل الدخول بالهاتف:** Authentication → Providers → Phone. اربط مزوّد رسائل (Twilio أو MessageBird أو Vonage).
   اختبر الإرسال لأرقام سودانية (+249) قبل الإطلاق، لأن التغطية والتكلفة تختلف بين المزوّدين.
   للتجربة المحلية يمكنك استخدام *Test phone numbers* داخل نفس الصفحة بدون إرسال رسائل حقيقية.
4. انسخ `.env.example` إلى `.env.local` وضع `NEXT_PUBLIC_SUPABASE_URL` و `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
5. `npm install` ثم `npm run dev` ثم افتح http://localhost:3000
6. **أول مدير:** سجّل الدخول مرة بحسابك، ثم من SQL Editor:
   ```sql
   update profiles set role = 'admin' where phone = '249912345678'; -- الرقم بدون +
   ```
   بعدها تظهر «الإدارة» في القائمة. الأدوار: `citizen` / `moderator` (بلاغات فقط) / `admin` (كل شيء).
7. من لوحة الإدارة ← المواقع أضف الأحياء الحقيقية لكل مدينة.

للنشر: Vercel مع نفس متغيّري البيئة.

## كيف يعمل التحقق من البلاغات

- كل بلاغ يُسجَّل في `reports` (سجل تدقيق دائم، لا يُحذف ولا يُعدَّل من التطبيق).
- بلاغ **يطابق** الحالة المؤكدة الحالية = تأكيد، يزيد عدّاد «أكّدوا الحالة».
- بلاغ **يخالفها** = «غير مؤكد» حتى يتفق عليه **N مستخدمين مختلفين** خلال 30 دقيقة (الافتراضي N=3، قابل للتعديل لكل حي).
  عندها يُنشأ سجل في `status_events` ويبدأ وقته من **أول بلاغ** في المجموعة.
- **كل الإحصائيات** (ساعات التشغيل/الانقطاع، عدد القطعات، الأسبوعي والشهري) تُحسب فقط من `status_events`.
  الوقت قبل أول حدث مؤكد يُعدّ «بلا بيانات» ولا يدخل في الحساب. الحساب بتوقيت الخرطوم (UTC+2).
- مشرف/مدير: بلاغه يُعتمد فوراً.

## حماية من السبام

- حساب برقم هاتف + OTP، وفاصل 10 دقائق بين بلاغين لنفس الحي، وحد 30 بلاغاً يومياً.
- منع تكرار نفس الحالة من نفس المستخدم، وتعليم البلاغ «مشبوه» تلقائياً عند 6 بلاغات أو 3 أحياء مختلفة خلال ساعة (لا تُحسب).
- لا يمكن للمستخدم تغيير دوره أو رفع صلاحياته (trigger + RLS). الكتابة على البلاغات تتم فقط عبر دالة `submit_report`.
- في صفحة الدخول حقل مصيدة (honeypot) ومهلة إعادة إرسال. للإنتاج أضف أيضاً CAPTCHA من إعدادات Supabase Auth.

## التوسّع لكل ولايات السودان

الجداول عامة (`states → localities → neighborhoods`). أضف ولاية من لوحة الإدارة ← المواقع، ولا يلزم تعديل في الكود.

## هيكل المشروع

```
supabase/migrations/0001_init.sql   قاعدة البيانات + RLS + الدوال
supabase/seed.sql                   الجغرافيا فقط
app/                                الرئيسية، /regions، /login، /profile، /admin
components/                         StatusCard, DayStrip, ReportButtons, StatsPanel, Timeline, admin/*
lib/                                supabase client, hooks (Realtime), format, periods, csv
```

## ملاحظات مهمة

- هذه بيانات **مواطنين** وليست مصدراً رسمياً؛ أبقِ هذا التنبيه ظاهراً.
- البلاغات المعلّقة لا تنتهي تلقائياً من السجل (تبقى للتدقيق) لكنها تتوقف عن العدّ بعد 30 دقيقة.
- رفض بلاغ سبق أن أنشأ حدثاً مؤكداً لا يلغي الحدث؛ لتصحيحه استخدم `admin_delete_event(event_id)` أو `admin_set_status(...)`.
